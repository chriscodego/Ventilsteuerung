# Core Implementation Checklist

## Layer Discipline
- [ ] No `PySide6` import anywhere in `core/` or `data/`
- [ ] Everything here is testable without a `QApplication`
- [ ] No `print()` — `logging.getLogger(__name__)` instead
- [ ] No network calls

## Models
- [ ] Checked existing models before adding new ones
- [ ] SQLAlchemy 2.0 style (`Mapped[...]` / `mapped_column(...)`)
- [ ] Index on every column used in WHERE, ORDER BY, or a join
- [ ] Foreign keys with the correct `ondelete` behaviour
- [ ] `UniqueConstraint` for every real-world uniqueness rule
- [ ] Datetimes stored in UTC
- [ ] Every attribute typed; `mypy src` passes

## Migration
- [ ] A migration exists for every schema change
- [ ] The autogenerated file was read and corrected by hand
- [ ] `downgrade()` implemented and actually works
- [ ] `alembic upgrade head && alembic downgrade -1 && alembic upgrade head` succeeds
- [ ] Tested against a database that already contains data — nothing is lost
- [ ] Destructive migrations back up the SQLite file first
- [ ] Any migration that drops or rewrites data was approved by the user

## Repositories
- [ ] All queries live in `data/repositories/` — none in services or UI
- [ ] Every method takes a `Session`; no repository creates its own
- [ ] `select()` used, not the legacy `session.query(...)`
- [ ] Unbounded reads capped with `.limit()` or paged

## Services
- [ ] Inputs validated in the service, not only in the UI
- [ ] Writes wrapped in `session_scope()`
- [ ] Domain exceptions raised; no `sqlalchemy.exc.*` leaks upward
- [ ] Write transactions kept short (SQLite has a single writer)
- [ ] No long-lived session held across user actions

## Security
- [ ] No secrets in source
- [ ] SQL parameters bound, never string-interpolated
- [ ] Imported files treated as untrusted: no `pickle`/`eval`/`yaml.load`, size caps, zip-slip guarded
- [ ] Writes go only to the user data directory or a path the user picked
- [ ] No personal data written to logs

## Tests
- [ ] Happy path covered per service method
- [ ] Validation failures raise the expected domain exception
- [ ] Constraint violations behave as specified
- [ ] Cascade behaviour tested
- [ ] Edge cases from the spec covered (empty input, malformed file, boundaries)
- [ ] Tests use the in-memory `db_session` fixture — the real user database is never touched

## Verification (run before marking complete)
- [ ] `ruff check src tests` passes
- [ ] `ruff format --check src tests` passes
- [ ] `mypy src` passes
- [ ] `pytest` passes
- [ ] All acceptance criteria from the feature spec are supported by the domain layer
- [ ] `features/INDEX.md` status updated to "In Progress"
- [ ] Code committed to git

## Performance Checklist
- [ ] Frequently filtered columns indexed
- [ ] No N+1 loops — use `selectinload` / `joinedload` for relationships
- [ ] List queries limited or paged
- [ ] Bulk inserts use `session.execute(insert(...), rows)` rather than a Python loop
- [ ] Verified with a realistic row count, not three test records
